# 사이트 구조와 핵심 문구 (2026-08-22 개편 기준)

콘텐츠 작성 기준은 `portfolio-content.md`를 따른다. 이 문서는 현재 화면 구성과 다음 개편 때 지켜야 할 결정만 남긴다.

## 첫 화면 (Hero)

- 한 화면 높이의 일반 섹션. 좌측 텍스트, 우측 픽셀 아트 이미지. 스크롤 연출 없음.
- 첫 화면 라벨, 제목과 설명 문구는 `portfolio-content.md`만 소유한다. `scripts/check-locked-content.mjs`가 구현과 가이드의 일치를 확인한다.
- 버튼은 주요 프로젝트 보기, GitHub 보기 두 개.
- 제거된 것: Build Trace(DEFINE~VERIFY 타임라인), PRODUCT SCOPE 다이어그램, 스크롤 단계 연출. 빈자리를 새 장식으로 채우지 않는다.

## 섹션 순서 (2026-08-22 개편)

첫 화면 → 경력(Career) → 주요 프로젝트 → 사이드 프로젝트 → 더 많은 작업과 대외 활동 → 기술 → AI 활용과 검증 → 취향 → 연락처. 경력을 프로젝트보다 앞에 두는 흐름은 junjange.github.io를 참고했다.

- 경력: 별도 소개 섹션을 없애고 리멤버 프로필의 경력 흐름을 압축한 두 문단을 타임라인 위에 둔다. 회사명 아래에는 제품 한 줄 소개(`intro`)를 둔다. 콘텐츠는 `src/data/experience.ts`.
- 사이드 프로젝트: 회사 경력 밖의 개인 프로젝트(Duckie, 꽥꽥). 동아리 활동은 대외 활동에 남긴다. 콘텐츠는 `src/data/sideProjects.ts`.
- 대외 활동: Mash-Up, YAPP 21기, Nexters 21기. YAPP 운영진과 YP QR은 기간과 담당 범위 확인 전이라 쓰지 않는다(NextStep `career/evidence/11-gaps.md`).
- 내비게이션은 Career, Projects, Side Project, Activity, Contact 다섯 개다.

## 주요 프로젝트

콘텐츠는 전부 `src/data/projects.ts`에 있다. 각 프로젝트는 좌우 분할이다. 왼쪽에 headline 한 문장, 역할과 문제 해결을 연결한 짧은 경력 글머리, 기술과 링크를 두고 오른쪽에 스크린샷 묶음을 둔다. 가로 화면은 한 줄을 다 쓰고 세로 화면은 개수에 맞춰 줄을 채우는 6칸 그리드다. 한 프로젝트가 한 화면에 들어오게 하려는 2026-08-23 개편이다. "담당/문제/판단/확인" 서사 단계와 격언식 제목은 추상적이라 2026-08-22 글머리로 교체했다. 우측 시각화(`ProjectDiagrams`)는 본문과 내용이 겹치고 전달하려는 메시지가 불분명해 2026-08-22 제거했다. 되살리려면 본문에 없는 정보를 보여 줄 때만 추가한다. "출시한 앱, 검증한 모델, ~ 보여드립니다" 헤드라인과 프로젝트 인덱스가 있던 도입 블록도 같은 날 제거했고 `#projects` 앵커는 장면 묶음 래퍼가 가진다.

각 프로젝트 글머리 아래에 앱 화면과 영상을 넣는다. 공개 파일, Figma 출처와 허용 범위는 `portfolio-content.md`의 공개 자산 승인 기록만 따른다. 이 문서에 자산 목록을 중복해 두지 않으며, 승인 기록 없이 새 사내 화면을 추가하지 않는다.

## 유지 결정

- 다크 테마, 큰 타이포그래피, 분할 레이아웃을 유지한다. 색은 2026-08-23 버건디로 확정했다. 표준 버건디 #800020이 어두운 배경에서 대비가 부족하다는 리서치에 따라 면과 버튼은 accent-strong(oklch 40% 0.155 17, #800020급)에 흰 글자, 텍스트 포인트는 밝힌 더스티 로즈 accent(oklch 70% 0.11 12)를 쓴다. 초록이 AI 느낌이라는 사용자 피드백에 따른 결정이다.
- 도트 게임 컨셉은 종료했다. IBM Plex Mono와 Silkscreen 의존성을 제거하고 라벨류(`--font-utility`)도 Pretendard로 통일했다 (2026-08-23). 히어로의 모눈 격자 배경도 같은 날 제거했고 넓은 자간(0.04~0.08em)은 0.02em으로 줄였다. 픽셀 아트 히어로 이미지는 아직 남아 있다.
- 푸터의 "AI에 맡긴 일도, 제품의 결과는 직접 확인합니다." 대형 문구는 의미가 약해 2026-08-23 제거했다. 푸터는 저작권과 맨 위로 링크만 남긴다.
- 좌측에 토스식 섹션 레일(`SectionRail.tsx`)을 둔다. 활성 섹션의 선이 길어지고 라벨이 나타난다. 900px 이하에서는 선만 남긴 축약형으로 바꾸고 480px 이하 모바일에서만 숨긴다. 첫 화면에서는 히어로와 겹치지 않도록 경력부터 나타나고, 상단 내비게이션도 같은 훅(`useActiveSection`)으로 현재 섹션에 밑줄을 켠다 (2026-08-25).
- 첫 화면에서 경력 구간에 들어오면 `App.tsx`의 IntersectionObserver가 main data-zone을 바꿔 배경을 paper에서 paper-2로 전환한다 (2026-08-23).
- 경력 제목 아래에 두 문단짜리 도입을 두며 첫 문단만 1.08~1.22rem로 강조한다. 전체 글자 크기는 루트 font-size 93.75%(15px 기준)로 한 단계 줄였다 (2026-08-23, 경력 병합 2026-08-25).
- 일반 섹션은 `Reveal`로 한 번만 순차 등장한다. 주요 프로젝트는 장면 진입 시 글과 미디어가 순차 등장하고, `Projects.tsx`의 IntersectionObserver가 활성 장면 id를 래퍼 data-scene에 써 배경색을 전환한다. 실제 화면은 개발 범위를 보여 주는 근거이므로 개별 화면을 과하게 강조하거나 스크롤을 점유하지 않는다. 스크롤 위치를 매 프레임 계산하는 미디어 패럴랙스와 Vuddy 화면별 강조 연출은 렉과 중요도 과장 문제로 제거했다 (2026-08-25).
- 마지막 Momentica 장면 아래쪽은 프로젝트 배경을 기본 배경으로 서서히 섞어 다음 `AI 활용과 검증` 섹션과 경계가 끊겨 보이지 않게 한다.
- 경력 상단 여백은 clamp(72px, 8vw, 112px), AI 활용은 clamp(88px, 10vw, 132px)다. 첫 화면과 경력 사이가 멀어지지 않도록 경력은 짧은 쪽 간격을 쓴다.
- Build Trace와 예전 다이어그램은 되살리지 않는다. 스크롤 연출은 현재 텍스트와 실제 프로젝트 화면을 읽기 쉽게 연결하는 범위에서만 사용한다.
- 수정 후 `npm run check` 실행. 잠긴 제목 문구를 바꾸려면 `docs/portfolio-content.md`와 검사 스크립트를 함께 고쳐야 한다.
