# 인터랙티브 홈페이지 설계 계획

## 목표와 독자

- 주인공: 최상록, Android Developer
- 주요 독자: Android 채용 담당자와 협업 상대
- 페이지의 한 가지 일: 2~3분 안에 `Android 제품을 출시까지 맡고, AI 결과는 직접 검증하는 개발자`라는 인상을 남긴다.
- 사실 기준: 현재 공개 포트폴리오와 NextStep 경력 근거 문서. 수치, 기여 범위와 외부 링크를 새로 만들지 않는다.

### 글꼴

- 제목과 본문: Pretendard Variable. 한글 가독성과 큰 제목의 밀도를 함께 유지한다.
- 기술과 상태: IBM Plex Mono Variable. 실제 구조, 입력과 확인 상태를 구분한다.
- 작은 장식 레이블: Silkscreen 10~12px. 인물명, 빌드 상태처럼 짧은 곳에만 사용한다.

### 레이아웃

- 인트로와 세 주요 프로젝트만 고정 스크롤 장면으로 만든다.
- 고정 장면 안에서는 왼쪽 문장 하나와 오른쪽 구조 하나만 우선해서 보여준다.
- 기술, AI 활용 방식, 경력과 활동은 일반 문서 흐름으로 이어 채용 담당자가 빠르게 훑을 수 있게 한다.
- Android 장면은 밝은 작업대, 모델 평가는 어두운 검증실로 구분한다.

### 대표 요소

`Build Trace`는 DEFINE, DESIGN, BUILD, SHIP, VERIFY 순서로 실제 개발 진행 상태를 보여준다. 별도의 스크롤 막대나 단계 번호 애니메이션은 만들지 않는다.

## 자기 비평과 수정

초안의 위험은 큰 제목과 고정 스크롤만으로 유명 제품 사이트의 형식을 빌리거나, 세 프로젝트를 같은 카드와 같은 휴대전화 목업으로 반복하는 것이다. 다음처럼 수정한다.

- 큰 제목은 작업실 프레임과 개발 연결선 안에서만 사용하고 다른 섹션에서는 줄인다.
- 세 프로젝트는 실제 판단 대상이 다른 SVG로 만든다. Vuddy는 통신 책임 경계, 모델은 평가 무결성, Momentica는 Android 시스템 실행 순서를 보여준다.
- 일반적인 성과 숫자와 가상 대시보드를 쓰지 않는다. 제약, 무효 처리와 확인 조건을 시각적 사건으로 쓴다.
- 장식용 단계 번호와 여러 진행 표시를 제거하고 Build Trace 하나만 남긴다.
- 도트 스타일은 10~12px 레이블과 작업실 이미지에만 남기고 전체 UI를 게임 화면처럼 만들지 않는다.
- 마지막 구현 검토에서 의미 없는 배경 효과나 반복 애니메이션 하나를 더 제거한다.

## 구현 경계

- Preact, Vite와 GitHub Pages의 `/` base path를 유지한다.
- 스크롤 진행률은 `requestAnimationFrame`에서 DOM 속성과 CSS 변수로만 갱신하고 Preact 상태를 매 프레임 바꾸지 않는다.
- JavaScript가 실패하면 모든 콘텐츠가 일반 문서 순서로 보이게 한다.
- `prefers-reduced-motion`, 800px 이하 화면에서는 고정 장면을 해제한다.
- 기존 `projects`, `skills`, `how-i-work`, `experience`, `contact` 앵커와 모든 외부 링크를 유지한다.
